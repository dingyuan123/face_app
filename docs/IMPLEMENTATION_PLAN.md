# 见面聊（FaceTo）第一阶段实施计划

## 当前实施状态

- T0-T8：代码已编写，基础静态检查已执行。
- T9：未完成。HBuilderX/UniApp x 实际编译、运行和多平台验证仍待执行。
- “完成”仅指代码实现完成，不等于编译和业务验证通过。

## 阶段目标

在不批量实现全部业务页面的前提下，完成登录、身份选择、普通用户首页、单页服务者申请四个页面及其必要基础能力，打通以下核心流程：

1. 游客打开首页并浏览公开内容。
2. 游客点击预约、聊天或收藏后被引导登录。
3. 开发测试入口切换普通用户、审核中、审核通过、审核拒绝状态。
4. 首次登录用户选择身份。
5. 选择普通用户后进入首页。
6. 选择服务者后填写并提交申请。
7. 查看审核中、审核通过、审核拒绝状态。
8. 审核拒绝后重新提交并保留历史。
9. 审核通过后个人中心出现工作台入口，但默认仍进入普通用户首页。

## 实施原则

- Android 优先验证，其他平台同步记录兼容性差异。
- 先基础能力，后页面。
- Mock 优先，但页面不得直接依赖 Mock 文件。
- 页面临时状态局部管理，跨页面必要状态使用轻量共享状态。
- 平台差异集中在适配层。
- 先使用现有结构，避免引入不必要依赖和复杂框架。
- 涉及核心业务规则、共享模型、原生插件、依赖和构建配置变更，先征求批准。

## 任务顺序

### T0：基线确认

- 再次确认设计源文件版本。
- 确认页面视觉、状态、文案和交互是否全部来源于设计源文件。
- 确认待确认问题中的数据范围、登录恢复动作和测试入口。
- 以已确认的五类申请字段为基线，补充核对图片规格、身份证信息形式、校验和隐私安全要求。
- 记录平台验证入口和目标构建方式。

**依赖**：无。
**产出**：设计对照表、待确认问题结论或明确的“待验证”标记。
**验收**：没有把未确认内容写成产品决定。

### T1：主题与公共 UI 基础

- 将品牌色、暖白背景、墨色、功能色、圆角、间距、阴影整理为稳定的主题令牌。
- 保持设计源文件中的页面结构和视觉优先级。
- 建立第一阶段需要的基础组件：
  - 品牌按钮
  - 输入框
  - 协议勾选
  - 状态标签
  - 卡片
  - 空态/加载/错误态基础表现
- 暂不建立完整组件库，避免过度设计。

**依赖**：T0。
**验收**：四个页面可以复用基础组件；颜色、圆角、间距在设计源文件中有对应关系。
**测试**：Android 优先查看静态页面；逐项记录其他平台未验证项。

### T2：共享模型与状态基础

建立并区分：

- 登录状态
- 身份选择状态
- 服务者申请状态
- 实际权限状态
- 当前用户公开/私有资料状态

定义稳定 ID、公开/私有数据边界、错误类型和状态持久化策略。

要求：

- 身份选择不等于服务者权限。
- 退出登录保留身份选择。
- 本地记录不能作为服务者权限凭证。
- 未提交申请表单不持久化。
- 审核历史需要持久化。
- 页面临时状态不进入共享状态。

**依赖**：T1 可并行，但状态模型应先于页面逻辑。
**验收**：四类状态可以独立读取、更新和恢复，且 Mock 权限不会被误当作真实权限。
**风险**：共享数据结构属于用户要求的变更前征求同意范围；实现前应先提交结构方案。

### T3：Mock/API 数据访问边界

- 按业务模块建立最小数据服务接口。
- Mock 实现与未来 API 实现分离。
- 明确公开接口与私有接口。
- 页面只调用业务数据服务，不直接导入 Mock 文件。
- 建立网络错误、业务错误、权限错误的区分处理。
- Mock 关键状态可持久化，开发测试状态可重置但仅限开发环境。

**依赖**：T2。
**验收**：切换 Mock/API 的影响被限制在数据服务层；错误不会伪装成成功。
**风险**：真实 API 协议尚未确认，第一阶段只建立足够使用的最小接口边界。

### T4：路由、登录引导与开发测试入口

- 注册四个页面路由。
- 建立公开页面、登录保护页面和权限保护页面的路由规则。
- 保存原始跳转页面和参数。
- 登录成功后恢复预约、聊天、收藏或原跳转目标。
- 未登录访问公开内容不强制登录。
- 私有数据访问必须拒绝并返回明确权限错误。
- 建立仅开发环境可见的测试入口，支持四种测试账号状态。
- 正式环境必须禁用测试入口、模拟审核和数据重置。

**依赖**：T2、T3。
**验收**：核心跳转、恢复和权限流程可重复验证；正式环境入口不暴露。
**风险**：路由守卫和登录恢复属于核心业务规则，设计需先确认。

### T5：登录页

实现：

- 手机号+短信验证码
- 微信登录
- Apple 登录
- 协议勾选和错误提示
- 游客进入公开页面
- 登录后恢复原始操作

要求：

- 不假设三种登录方式在四个平台都可用。
- 平台不可用时显示明确的平台能力状态，不伪造成功。
- 登录成功默认进入普通用户首页，不自动进入工作台。

**依赖**：T1-T4。
**验收**：开发测试登录可走通；真实登录方式的平台实现分别标记已验证/待验证。

### T6：身份选择页

实现普通用户、服务者两种身份选择及首次进入规则。

- 选择普通用户 → 普通用户首页。
- 选择服务者 → 单页服务者申请页。
- 不提供身份切换。
- 身份选择与服务者权限解耦。

**依赖**：T2、T4。
**验收**：首次登录、退出登录后保留身份、待审核和拒绝状态路径均符合产品规则。

### T7：普通用户首页

实现设计源文件 C04 范围内的首页基础版本：

- 城市定位入口
- 搜索入口
- 消息入口
- 分类导航
- 服务者动态卡片流
- 收藏、私信、预约操作
- 游客公开浏览和登录引导

第一阶段不要求实现完整搜索、聊天、订单和动态详情业务。

**依赖**：T1、T3、T4、T6。
**验收**：游客可浏览；账号操作触发登录并恢复目标；Mock 数据不被页面直接导入。

### T8：单页服务者申请页

实现统一提交的单页申请表单。

当前字段基线：

- 头像。
- 生活照。
- 个人简介。
- 真实姓名。
- 身份证信息。

字段模型应支持后续继续补充申请资料。字段校验、图片规格、身份证信息形式和资料上传能力按已确认规则与设计源文件实现。
- 提交防重复。
- 不保存未提交草稿。
- 离开后未提交内容清空。
- 提交后显示审核中。
- 审核拒绝显示原因，可修改后重新提交。
- 保留历史申请和审核记录。
- 审核通过后在个人中心出现工作台入口。

**依赖**：T2、T3、T4、T6。
**验收**：审核中、通过、拒绝、重新提交四条路径可重复验证。
**风险**：五类字段基线已经确认，但身份证信息和照片属于敏感个人信息，具体采集形式、图片规格、上传存储、访问控制、日志脱敏和删除策略仍需在实现前确认。申请历史属于核心共享数据结构，具体模型实施前仍需征求同意。

### T9：第一阶段回归与平台验证

- 检查代码规范和 UTS/`.uvue` 语法。
- 检查业务规则、状态分离和权限边界。
- 对照设计源文件检查 C03、C04、C36 和身份选择页。
- Android 优先构建验证。
- 有条件时验证 iOS、HarmonyOS、微信小程序。
- 记录每个平台的真实结果、失败原因和待验证事项。
- 检查正式环境无测试入口。

**依赖**：T5-T8。
**验收**：九条核心流程均有真实验证结果；未验证内容明确列出，不能写成通过。

## 测试方法

### 功能流程测试

- 游客浏览公开内容。
- 游客触发预约/聊天/收藏登录引导。
- 登录后恢复原始目标。
- 首次登录进入身份选择。
- 普通用户进入首页。
- 服务者提交申请。
- 审核中、拒绝、通过、重新提交。
- 退出登录后身份保留但权限正确失效。
- 开发测试入口切换四种状态。

### 状态与数据测试

- 未提交申请表单离开后不恢复。
- 已提交申请历史可恢复。
- 本地身份不授予服务者权限。
- 私有数据接口对游客返回权限错误。
- 网络错误、业务错误、权限错误分别展示。
- Mock 切换不影响页面直接依赖。

### UI 检查

- 品牌色、暖白背景、品牌墨色、圆角、间距和阴影与设计源文件一致。
- 按钮、输入框、协议、状态标签、卡片和空态/错误态一致。
- 不擅自改变页面结构和主题。

### 兼容性检查

- Android 优先。
- iOS、HarmonyOS、微信小程序分别记录编译、导航、登录、图片/资料上传和生命周期差异。
- 平台不支持的能力必须报告，不以 Mock 结果冒充真实平台通过。

## 可能的阻塞项

1. 设计源文件缺失或版本不明。
2. 服务者申请五类字段基线已确认，但身份证信息形式、图片规格、上传存储和审核历史模型仍待确认。
3. 微信、Apple、短信登录的真实平台配置和后端协议未确认。
4. HBuilderX/UniApp x/UTS/Vapor 的平台编译能力未验证。
5. 微信小程序 appid、iOS 签名和 HarmonyOS 配置未准备。
6. 真实 API 协议未确认，无法完成 Mock/API 最终切换。
7. 原生插件、依赖和构建配置变更尚未获得批准。

## 第一阶段完成定义

只有在以下条件全部满足时，才可将第一阶段标记为完成：

- 四个页面和基础能力已实现。
- 九条核心流程已实际走通。
- 代码、业务、UI、兼容性检查已完成并有记录。
- Android 结果明确；其他平台已验证或明确列为待验证。
- 正式环境不暴露开发测试入口和模拟权限。
- 未验证事项没有被误报为已完成。
