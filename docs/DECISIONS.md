# 见面聊（FaceTo）决策记录

本文件记录用户明确确认的产品与架构约束，以及尚待确认、尚待验证的事项。标记为“已确认”的内容来自当前任务和已确认产品规则；标记为“待确认”或“技术待验证”的内容不得当作最终结论。

## 已确认

### 产品与范围

- 项目名称：见面聊（FaceTo）。
- 客户端技术：UniApp x、Vue 3、UTS、`.uvue`。
- 目标平台：Android、iOS、HarmonyOS、微信小程序。
- 开发优先级：Android 优先验证，同时兼顾其他目标平台。
- 管理后台独立于本客户端项目。
- 第一阶段只打通四个页面及相关基础能力：
  1. 登录页
  2. 身份选择页
  3. 普通用户首页
  4. 单页服务者申请页
- 第一阶段不批量实现全部业务页面，不开发独立管理后台。

### 登录与游客

- 正式登录方式：手机号+短信验证码、微信登录、Apple 登录。
- 各登录方式的实际可用性必须按平台和 UniApp x 能力核实。
- 游客可浏览首页、服务者主页、服务详情等公开内容。
- 预约、聊天、收藏等账号操作才触发登录引导。
- 登录后尽可能恢复用户原本想执行的操作及参数。
- 游客不能读取个人资料、订单、收藏、聊天记录等私有数据。

### 身份、服务者申请与权限

- 首次进入且未选择身份时进入身份选择页。
- 身份为普通用户、服务者，不提供身份切换。
- 选择普通用户后进入普通用户首页。
- 选择服务者后进入单页服务者申请表单。
- 当前申请字段基线为：头像、生活照、个人简介、真实姓名、身份证信息。字段模型需要可扩展，后续可能继续补充申请资料。
- 申请表单统一提交，不自动保存未提交草稿；离开后未提交内容清空。
- 提交操作必须防止重复提交。
- 身份选择不等于获得服务者权限。
- 待审核、审核拒绝用户仍可使用普通用户功能。
- 待审核时个人中心显示审核进度。
- 审核拒绝时显示拒绝原因，允许修改后重新提交，并保留历史申请和审核记录。
- 审核通过后个人中心出现工作台入口。
- 登录成功默认进入普通用户首页，不自动跳转工作台。
- 登录状态、身份选择、服务者申请状态和实际权限分别管理。
- 退出登录后保留已选择身份，但本地记录不能作为服务者权限凭证。

### 开发测试与数据

- 开发环境提供独立测试登录入口，可模拟普通用户、审核中、审核通过、审核拒绝。
- 正式环境不得暴露测试入口、模拟审核或测试数据重置功能。
- Mock 关键业务状态需要持久化；未提交申请表单不持久化。
- 页面不得直接导入 Mock 数据文件。
- 公开接口与私有接口明确区分。
- 各业务模块拥有自己的数据服务和 Mock 实现。
- 跨模块实体使用稳定 ID 和共享业务类型。
- 网络错误、业务错误、权限错误分别处理，不伪造成功。

### 设计约束

- 最新设计源文件为页面结构和视觉的首要依据。
- Figma 为补充参考；设计文档与 Figma 冲突时必须报告。
- 品牌色：珊瑚粉 `#FD5A6B`、渐变中间色 `#FD955E`、暖橙 `#FCAE59`、品牌墨色 `#1F1A17`，背景为白色及暖白色系。
- 不擅自改变已确认页面结构或主题。

### 开发治理

- 核心架构、共享模型、核心业务规则及高风险操作变更前征求用户同意。
- 新增原生插件、第三方依赖或修改构建配置前征求用户同意。
- 不覆盖用户现有修改，不自动提交、推送或合并 Git。
- 开发任务完成后进行代码、业务、UI、兼容性检查。

### 第一阶段技术实现

- 四个页面沿用当前 HBuilderX 项目根目录结构，新增 `components`、`types`、`state`、`services`、`router` 和页面子目录，不引入 npm 依赖。
- 页面只通过 `services/service-container.uts` 访问业务数据；Mock 实现位于服务层内部，页面不得直接导入。
- 登录状态、身份选择、服务者申请状态和权限状态分开存储。
- 开发测试入口仅在 `process.env.NODE_ENV == 'development'` 时显示。
- Mock 持久化申请历史和状态，不持久化未提交表单，不保存明文身份证号，只保存脱敏摘要。
- 为保持第一阶段“四个页面”范围，个人中心先作为普通用户首页中的轻量面板实现；独立个人中心页面留到后续阶段。
- 微信、Apple 登录入口已经展示，但在真实平台授权和配置完成前只返回明确的未配置结果，不伪造登录成功。
- 首页动态封面数据模型使用 `coverImages: string[]`，服务者至少提供多张照片；首页固定高度区域展示首三张组合图，超过三张显示数量角标。
- 动态封面和头像使用项目内品牌插画 PNG，后续真实数据只需替换 `coverImages`、`providerAvatar` 或 `avatar` 的图片地址。

### C07/C09/C11/C19 一级页面实现

- C07 动态、C09 资讯、C11 消息、C19 我的均为一级页面，并与既有首页统一使用 UniApp x 原生 `tabBar`。原自定义底部导航会因页面重建闪烁，已停止在页面中引用。
- C19 独立个人中心完成后，首页原轻量“我的”面板由正式个人中心页面替代。
- 动态和资讯属于公开内容；关注动态、消息列表和账号资料属于私有内容。
- 私有页面对游客展示明确登录引导，登录后返回原页面。
- 页面仍只通过 `services/service-container.uts` 访问数据，新增动态、资讯、消息和资料 Mock 服务。
- 当前未实现 C08、C10、C12 及个人中心子页面，相关入口只显示后续阶段提示，不伪造完成状态。

### C05 搜索页实现

- 使用用户提供的 Figma 首页搜索页截图和现有 C05 设计说明还原默认搜索状态。
- FaceTo 字标、返回、搜索、语音、垃圾桶、定位、盾牌和星光图标使用项目内绘制的替代 PNG，未引入外部图片依赖。
- 搜索历史和热门搜索使用页面局部 Mock 状态。
- 搜索结果页、语音搜索和附近陪伴跳转属于后续页面/能力，本阶段只提供明确提示，不伪造完成。

### C06 搜索结果页实现

- 根据用户提供截图和 C06 设计说明开发，默认支持“全部/服务者/服务/动态/资讯”五类结果。
- 对截图中的混合结果卡片做了统一化优化：统一卡片边界、标题、摘要、标签、价格和操作层级。
- 搜索结果使用 Mock 数据，页面只通过统一服务访问数据。
- 搜索框返回 C05 时保留当前搜索词。
- 搜索结果详情、更多筛选、预约、聊天和资讯详情暂未实现，入口只显示后续阶段提示。
- 首页分类、动态/资讯/消息 Tab、搜索结果 Tab/筛选 Chip 统一使用 `SegmentTabs` 组件，横向内容不足时可滚动，超出项不会被裁切。
- 搜索结果服务者与服务价格统一使用固定宽度价格块，避免价格挤压标签或与相邻内容过于紧凑。

### C13/C14/C08 详情页实现

- C13 服务者主页支持媒体照片墙、服务者资料、关注/收藏、动态/服务 Tab、服务卡片和底部预约入口。
- C14 服务详情支持媒体展示、服务内容、预约日期、公共场所要求、评价区和固定预约栏。
- C08 动态详情按抖音式沉浸视频页实现：全屏媒体、暂停/声音、点赞、评论、分享、服务入口、作者信息和话题位置。
- 首页卡片封面和“立即预约”统一进入 C13 服务者主页。
- 服务者主页服务卡进入 C14，动态卡进入 C08。
- C15 下单页、评论区、分享能力和真实视频播放尚未接入，相关入口只提供明确提示。
- 服务者主页和服务详情媒体封面使用 UniApp x `swiper` 横向轮播。
- 动态详情使用 UniApp x `swiper` 纵向视频流，支持上下滑动切换动态。

### C15/C16 下单与支付结果实现
