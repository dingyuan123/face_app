# 见面聊（FaceTo）决策记录

本文件记录用户明确确认的产品与架构约束，以及尚待确认、尚待验证的事项。标记为“已确认”的内容来自当前任务和已确认产品规则；标记为“待确认”或“技术待验证”的内容不得当作最终结论。

## 重要技术决策与原因

以下为已确定的技术决策汇总；详细上下文见后文各章节。「待确认」「技术待验证」中的内容不属于已确定决策。

| # | 决策 | 原因 |
|---|---|---|
| 1 | 沿用 HBuilderX 项目根目录结构，不引入 npm/第三方依赖 | UniApp x + UTS 由 HBuilderX 工具链编译，引入包管理会增加构建不确定性；现有能力已覆盖需求 |
| 2 | 页面只通过 `services/service-container.uts` 访问数据 | 页面与数据实现解耦；Mock 与真实 API 可在服务层切换，页面不感知 |
| 3 | API 配置集中在 `services/api-config.uts`，请求集中在 `api-client.uts` | 测试域名变更为正式域名时只改一处；Token、幂等键、401、超时、响应解析统一处理 |
| 4 | 登录态、身份选择、入驻申请状态、服务者权限分开管理，本地不缓存权限凭证 | 产品规则要求四者互不等同；本地记录冒充权限会造成越权 |
| 5 | 退出登录清理身份/申请/权限状态，下次登录以后端 `/users/me/` 为准 | 后端是身份与权限权威来源，避免本地残留误导 |
| 6 | 测试账号（`test-`/`mock-` 前缀）走 Mock，真实账号走 API | 开发测试入口需要模拟四种审核状态；Mock 权限不得冒充真实权限 |
| 7 | 一级导航使用 UniApp x 原生 `tabBar`，弃用自定义底部导航组件 | 自定义组件切换页面时重建导致闪烁（Android 真机实测） |
| 8 | 媒体展示使用后端短期签名 `display_url` | 后端媒体接口有鉴权，`<image>` 无法带 Authorization；签名直链免鉴权且可过期 |
| 9 | 资源修改带 `expected_version`、写操作带 `Idempotency-Key` | 防并发覆盖与重复提交（申请、服务、动态等） |
| 10 | 派生列表/统计值在刷新函数显式生成赋值，禁止数组型 `computed` | Android 真机 Vapor 渲染迭代响应式数组时触发 `ConcurrentModificationException`（实测崩溃） |
| 11 | 样式遵守 UniApp x 子集（禁后代/兄弟选择器、`display` 仅 flex/none、`align-items` 四值、`rpx`） | 编译器不支持的属性/选择器在真机出现警告或失效 |
| 12 | 固定底部操作栏放在纵向 `scroll-view` 外层 | 否则被内容遮挡或无法滚动到底（Android 真机实测） |
| 13 | 视觉以设计源文件为准，Figma 为补充，冲突先报告 | 设计源是用户确认的基准，避免 AI 自行猜测视觉 |
| 14 | 服务者动态当前仅支持图文（`IMAGE_TEXT`）；动态类型、可见范围以后端接口能力为准 | 后端接口当前限制，不伪造视频动态/仅粉丝可见成功 |

## 已确认

### 产品与范围

- 项目名称：见面聊（FaceTo）。
- 客户端技术：UniApp x、Vue 3、UTS、`.uvue`。
- 目标平台：Android、iOS、HarmonyOS、微信小程序。
- 开发优先级：Android 优先验证，同时兼顾其他目标平台。
- 管理后台独立于本客户端项目。
- 第一阶段只打通四个页面及相关基础能力：
  1. 登录页
  2. 身份选择页
  3. 普通用户首页
  4. 单页服务者申请页
- 第一阶段不批量实现全部业务页面，不开发独立管理后台。

### 登录与游客

- 正式登录方式：手机号+短信验证码、微信登录、Apple 登录。
- 各登录方式的实际可用性必须按平台和 UniApp x 能力核实。
- 游客可浏览首页、服务者主页、服务详情等公开内容。
- 预约、聊天、收藏等账号操作才触发登录引导。
- 登录后尽可能恢复用户原本想执行的操作及参数。
- 游客不能读取个人资料、订单、收藏、聊天记录等私有数据。

### 身份、服务者申请与权限

- 首次进入且未选择身份时进入身份选择页。
- 身份为普通用户、服务者，不提供身份切换。
- 选择普通用户后进入普通用户首页。
- 选择服务者后进入单页服务者申请表单。
- 当前申请字段基线为：头像、生活照、个人简介、真实姓名、身份证信息。字段模型需要可扩展，后续可能继续补充申请资料。
- 申请表单统一提交，不自动保存未提交草稿；离开后未提交内容清空。
- 提交操作必须防止重复提交。
- 身份选择不等于获得服务者权限。
- 待审核、审核拒绝用户仍可使用普通用户功能。
- 待审核时个人中心显示审核进度。
- 审核拒绝时显示拒绝原因，允许修改后重新提交，并保留历史申请和审核记录。
- 审核通过后个人中心出现工作台入口。
- 登录成功默认进入普通用户首页，不自动跳转工作台。
- 登录状态、身份选择、服务者申请状态和实际权限分别管理。
- 退出登录后清理身份选择、申请状态和权限状态；下一次登录以后端返回结果为准，本地记录不能作为服务者权限凭证。

### 开发测试与数据

- 开发环境提供独立测试登录入口，可模拟普通用户、审核中、审核通过、审核拒绝。
- 正式环境不得暴露测试入口、模拟审核或测试数据重置功能。
- Mock 关键业务状态需要持久化；未提交申请表单不持久化。
- 页面不得直接导入 Mock 数据文件。
- 公开接口与私有接口明确区分。
- 各业务模块拥有自己的数据服务和 Mock 实现。
- 跨模块实体使用稳定 ID 和共享业务类型。
- 网络错误、业务错误、权限错误分别处理，不伪造成功。

### 设计约束

- 最新设计源文件为页面结构和视觉的首要依据。
- Figma 为补充参考；设计文档与 Figma 冲突时必须报告。
- 品牌色：珊瑚粉 `#FD5A6B`、渐变中间色 `#FD955E`、暖橙 `#FCAE59`、品牌墨色 `#1F1A17`，背景为白色及暖白色系。
- 不擅自改变已确认页面结构或主题。

### 开发治理

- 核心架构、共享模型、核心业务规则及高风险操作变更前征求用户同意。
- 新增原生插件、第三方依赖或修改构建配置前征求用户同意。
- 不覆盖用户现有修改，不自动提交、推送或合并 Git。
- 开发任务完成后进行代码、业务、UI、兼容性检查。

### 第一阶段技术实现

- 四个页面沿用当前 HBuilderX 项目根目录结构，新增 `components`、`types`、`state`、`services`、`router` 和页面子目录，不引入 npm 依赖。
- 页面只通过 `services/service-container.uts` 访问业务数据；Mock 实现位于服务层内部，页面不得直接导入。
- 登录状态、身份选择、服务者申请状态和权限状态分开存储。
- 开发测试入口仅在 `process.env.NODE_ENV == 'development'` 时显示。
- Mock 持久化申请历史和状态，不持久化未提交表单，不保存明文身份证号，只保存脱敏摘要。
- 为保持第一阶段“四个页面”范围，个人中心先作为普通用户首页中的轻量面板实现；独立个人中心页面留到后续阶段。
- 微信、Apple 登录入口已经展示，但在真实平台授权和配置完成前只返回明确的未配置结果，不伪造登录成功。
- 首页动态封面数据模型使用 `coverImages: string[]`，服务者至少提供多张照片；首页固定高度区域展示首三张组合图，超过三张显示数量角标。
- 动态封面和头像使用项目内品牌插画 PNG，后续真实数据只需替换 `coverImages`、`providerAvatar` 或 `avatar` 的图片地址。
